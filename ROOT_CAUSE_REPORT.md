## Training-contract conclusion

The production manifest fixes the 17-channel order and 128-pixel patch size. The training preprocessing stores Q as `clip(n_clear / 8, 0, 1)` for multi-date composites. The checked-in protocol applies spatial heterogeneity to the raw count (`std(n_clear) > 0.5`), before the Q scaling/clipping; consequently a constant Q map can still satisfy the trained criterion when raw counts vary above the clipping ceiling. Its monsoon single-date benchmark instead uses continuous `cs_cdf`; that is a separate data product and is not what the current runtime builds. Therefore validation must distinguish unavailable/placeholder Q from genuine acquisition, check the encoded Q range/nodata, and apply the heterogeneity gate to raw `n_clear` statistics—not infer raw variation from already-clipped Q.

The production checkpoint, architecture, and train-only normalization are unchanged. The release manifest supplies a SHA-256 for the production checkpoint; the existing regression test exercises strict loading and one inference patch. Live GEE availability and the exact provider for the reported user request remain unverified without the corresponding server log and credentials.
